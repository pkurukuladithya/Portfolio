Why this idea came

From a simple motor demo to an industry-style IIoT system.

Industrial motors, fans, pumps, and rotating machines can fail due to abnormal vibration, unusual sound, current overload, overheating, or bearing issues. In real factories, these failures can create downtime and maintenance cost. I wanted to build a realistic low-cost system that demonstrates how machine health can be monitored continuously using embedded systems and IIoT architecture.

Problem

  • Manual inspection is not continuous.
  • Faults are often detected late.
  • Commercial PLC/SCADA systems are expensive for student-level prototyping.
  • Many projects stop at sensor reading and do not show a full industrial data path.

Solution

  • Real-time vibration, acoustic, and power monitoring.
  • PLC-style motor control using Arduino and RS485.
  • ESP32-S3 intelligent edge layer with FreeRTOS.
  • Raspberry Pi edge server with MQTT, database, and dashboard.

System architecture

Three engineering layers working together.

The system is intentionally separated into a PLC simulation layer, an intelligent embedded layer, and a Raspberry Pi edge server layer to represent a real industrial environment.

Layer 01

PLC Simulation Layer

Arduino UNO controls the actuator side like a simple PLC. It receives commands and controls the fan/motor through TB6612.

Hardware: Arduino UNO, TB6612, INA3221

Communication: RS485 text protocol

Equivalent: PLC / actuator controller

Layer 02

Intelligent Embedded Layer

ESP32-S3 collects vibration and acoustic data, communicates with the PLC layer, calculates health state, and sends MQTT telemetry.

Hardware: ESP32-S3, ADXL345, INMP441, MAX485

Firmware: C++ with FreeRTOS tasks

Equivalent: IIoT sensor gateway

Layer 03

Raspberry Pi Server Layer

Raspberry Pi works as the local edge server with MQTT broker, backend API, database, Docker deployment, and dashboard.

Services: Mosquitto, FastAPI, InfluxDB, React

Deployment: Docker Compose

Equivalent: Edge gateway / local server

Hardware development

From jumper testing to custom PCB design.

The hardware was designed step by step. First each module was verified individually, then integrated into layers, then converted into cleaner PCB carrier designs for reliability and professional presentation.

Step 1 · Machine demo selection

A 12V fan/motor is used as a safe rotating machine demo to simulate industrial fans, pumps, or motors.

Step 2 · Sensor selection

ADXL345 measures vibration, INMP441 monitors acoustic/noise behavior, and INA3221 measures current, voltage, and power.

Step 3 · PLC and intelligent boards

Arduino handles actuator control while ESP32-S3 handles sensor intelligence, WiFi, MQTT, and RS485 gateway functions.

Step 4 · Why PCB?

PCB design reduces messy wiring, improves power distribution, creates clear terminal labels, adds decoupling capacitors and pull-up resistors, and makes the project presentation closer to an industrial prototype.
